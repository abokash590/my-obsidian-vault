# Harmonic Series Technique — Number Theory

A common pattern in number theory / competitive programming for problems involving divisors, multiples, or sieve-like enumeration.

## The Idea

For each `i` from `1` to `N`, iterate over all multiples of `i` (i.e., `i, 2i, 3i, ...` up to `N`). The total number of operations across all `i` is:

```
N/1 + N/2 + N/3 + ... + N/N ≈ N · ln(N)
```

This sum is the **harmonic series**, hence the name. Even though it looks like a nested loop (which might suggest O(N²)), the actual complexity is **O(N log N)**.

## Code (C++)

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;

    vector<int> divisor_count(n + 1, 0);

    // Harmonic series loop
    for (int i = 1; i <= n; i++) {
        for (int j = i; j <= n; j += i) {
            divisor_count[j]++;   // j is divisible by i
        }
    }

    for (int i = 1; i <= n; i++) {
        cout << i << " has " << divisor_count[i] << " divisors\n";
    }
}
```

## Input / Output

**Input:**

```
10
```

**Output:**

```
1 has 1 divisors
2 has 2 divisors
3 has 2 divisors
4 has 3 divisors
5 has 2 divisors
6 has 4 divisors
7 has 2 divisors
8 has 4 divisors
9 has 3 divisors
10 has 4 divisors
```

Here, `n` is the input (upper bound), and the output is the divisor count for every number from `1` to `n` — computed using the harmonic-series double loop instead of checking divisibility individually for each number.

## Complexity Summary

|Approach|Complexity|
|---|---|
|Naive (check each divisor for each number)|O(N√N)|
|Harmonic series enumeration|**O(N log N)**|

## Where This Pattern Appears

This same technique shows up in:

- **Sieve of Eratosthenes**
- **Divisor sum problems**
- **GCD-sum problems**
- **Möbius function computations**

— anywhere you're marking or updating multiples of every number up to N.

## Related Technique

A related but distinct idea is computing `Σ floor(N/i)` using **sqrt decomposition / block division**, where the range of `i` is partitioned into blocks where `floor(N/i)` stays constant, giving O(√N) per query instead of O(N).
