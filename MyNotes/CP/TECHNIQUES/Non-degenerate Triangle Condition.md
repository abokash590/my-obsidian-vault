**Non-degenerate Triangle** (অ-ক্ষয়প্রাপ্ত বা বাস্তব ত্রিভুজ) বলতে এমন একটি ত্রিভুজকে বোঝায় যার ক্ষেত্রফল (Area) সবসময় শূন্যের চেয়ে বড় ($> 0$) হয়। যদি ৩টি বাহু কোনো একটি সরলরেখার ওপর অবস্থান করে (Collinear হয়), তবে সেটিকে **Degenerate Triangle** বলা হয় (যার ক্ষেত্রফল ০)।

---

### 🧠 The Core Insight: Triangle Inequality Theorem

যেকোনো ৩টি বাহু $a$, $b$, এবং $c$ দিয়ে একটি বৈধ ত্রিভুজ গঠন করা সম্ভব তখনই, যখন **যেকোনো দুটি বাহুর যোগফল তৃতীয় বাহুর চেয়ে বড় হয়**।

গাণিতিকভাবে শর্তটি হলো:

1. $a + b > c$
    
2. $b + c > a$
    
3. $c + a > b$
    

---

### 🚀 Optimization Tip (কন্টেস্টের সময় দ্রুত করার জন্য)

প্রতিবার ৩টি কন্ডিশন আলাদাভাবে চেক না করে, তুমি যদি বাহু ৩টিকে ছোট থেকে বড় ক্রমানুসারে সাজিয়ে নাও (Sorted order: $a \le b \le c$), তবে শুধু **একটি** কন্ডিশন চেক করলেই চলে:

$$\text{If } a \le b \le c, \text{ then the condition is: } a + b > c$$

### 💻 Validity Check Function (C++)

নিচে `std::sort` ব্যবহার করে সবচেয়ে এফিশিয়েন্ট উপায়ে শর্তটি চেক করার ফাংশন দেওয়া হলো:

C++

```cpp
bool isValidTriangle(int a,int b,int c) {
 return ((a+b>c)&&(b+c>a)&&(c+a>b));
}
```

### ⚠️ Common Mistakes & Edge Cases (Pupil Level Pitfalls)

১. **Integer Overflow (`long long`):** কোডফোর্সেসে অনেক সময় বাহুর দৈর্ঘ্য $10^9$ পর্যন্ত দেওয়া থাকে। তখন দুটির যোগফল (`a + b`) করলে তা স্ট্যান্ডার্ড `int`-এর রেঞ্জ ছাড়িয়ে ওভারফ্লো করতে পারে। তাই প্যারামিটার হিসেবে সবসময় `long long` ব্যবহার করা নিরাপদ।

২. **Degenerate Case ($a + b == c$):**

যদি দুটি বাহুর যোগফল তৃতীয় বাহুর একদম সমান হয়, তবে সেটি একটি সোজা দাগ (Straight Line) তৈরি করবে, ত্রিভুজ নয়। প্রশ্নে যদি **Non-degenerate** বলা থাকে, তবে `=` কন্ডিশন দেওয়া যাবে না, শুধু `>` দিতে হবে।
